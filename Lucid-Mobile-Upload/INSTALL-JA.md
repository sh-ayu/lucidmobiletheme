# Lucid Mobile Settings の導入

1. このフォルダーの中身をGitHubの既存 `sh-ayu/lucidmobiletheme` のルートにアップロードします。pluginフォルダーの階層を保ちます。
2. KettuでテーマのLucidを選択したまま、PluginsのURL追加から次を入れます。
   https://raw.githubusercontent.com/sh-ayu/lucidmobiletheme/refs/heads/main/plugin/
3. Lucid Mobile Settingsを有効にして、そのプラグインの設定を開きます。
4. プリセットかHEX、背景表示、見えやすさ20〜85を設定して「適用」を押します。配色と背景画像が選択色から生成されます。

## 既に導入済みの場合（2.3.1・互換処理の対象判定修正）

今のリポジトリではこのフォルダーをLucid-Mobile-Uploadという名前で公開しています。同じ場所へ上書きアップロードしてください。
既存のプラグイン詳細でRefetchを押して更新し、設定上部に「Spotify対応 2.3.1」と表示されたことを確認します。
既存のURL: https://raw.githubusercontent.com/sh-ayu/lucidmobiletheme/refs/heads/main/Lucid-Mobile-Upload/plugin/
自動で連動させる場合は「Spotify連動」をオンにしてください。曲名・ジャケット・抽出色が表示されます。
手動配色の変更は従来の「適用」を使います。
「ジャケットのぼかし」3、「ジャケットの濃さ」65が既定です。
2.1.1では設定内の説明文・曲名の暗すぎる文字色を修正し、「上下の配色を確認」を追加しました。
このボタンで表示される配色診断のスクリーンショットを共有すると、適用データ、JS解決色、起動時ローダー色の食い違いを確認できます。
診断は押したときだけ実行し、外部送信・設定の書き換えは行いません。アカウント情報・曲名・認証情報は含めません。
2.2.0では現行モバイルのBACKGROUND_BASE_*、BACKGROUND_SURFACE_*、MOBILE_KEYBOARD_*の背景色と、現行の文字・アイコン色を定義しました。Spotify連動中は自動再適用され、手動配色なら「適用」で更新できます。
2.3.0は色解決エラーを補う互換処理を追加しました。Lucid選択中の現在のカスタムテーマ文脈で、公開APIから特定できる色の解決が例外になった場合だけ、適用中の配色値を返します。通常の解決・別テーマ・プロフィール固有色には介入しません。停止で解除します。
2.3.1では現在のテーマ文脈が通常のdarkerのままでも、選択中のLucidの既知の色に限ってエラーを補います。違うテーマ文脈には介入しません。
「上下の配色を確認」で復帰回数に加え、補正経路の呼出回数、現在の文脈、最後の対象外理由を確認できます。強制停止を繰り返す必要はありません。この版でのAndroid実機の上下の最終描画は未確認です。

テーマ用JSONのURLとプラグインのURLは別です。このプラグインURLは上記アップロード後に使えます。
「元のテーマに戻す」、またはプラグインの無効化で元のLucidへ戻せます。
テーマを更新した場合、更新を優先します。再度カスタマイズする場合は「適用」を押してください。

Spotify連動をオンにすると自分の再生Presenceとジャケットに背景・配色が追従します。画像解析は端末内です。
音声解析・再生操作・統計は含みません。
配布JSの読み込み、設定ツリー、復元、型検査は分離テスト済みですが、この補助プラグインの実機動作は未検証です。
元のテーマは利用者から導入・外観の良好な報告を受けています。
